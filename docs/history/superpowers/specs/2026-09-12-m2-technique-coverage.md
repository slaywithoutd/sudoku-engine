Expected fixture IDs below describe acceptance requirements; they are not evidence by themselves. A missing fixture or implementation blocks marking that row verified and blocks declaring the expanded M2 profile complete. Reviewable batch delivery is permitted; a six-technique build is an intermediate kernel. If a bounded form proves impractical, record the failed gate and seek an explicit scope revision; never silently remove the family or call it covered by an unrelated solver path.

Implement `CoverageEntry` in `solver/techniques/manifest.ts`: `{id, version, aliases, tier, capabilities, assumptionPolicy, bounds, grammarId, detectorId, checkerId, descriptionPath, fixtureIds, status}`. Status enum: `catalogued | specified | implemented | independently-verified | unsupported`. Every alias maps to exactly one primary grammar plus optional named specialization. An unsupported alias includes a reason and nearest supported form. Build validation rejects verified rows without positive, negative, boundary, original-clue and independent-oracle records. UI shows both static support status and this run's exhausted/interrupted ledger.

Capabilities below: **D** domains/cell-exactly-one; **A** all-different; **H** symbol covers; **G** verified weak/strong implication graph; **R** proved finite relations; **K** classic row/column/box geometry. **U** means independent unique evidence plus rule-preserving transformation. Policy **P** is unconditional, **Dsc** allows only fully discharged hypotheses, **U** stays conditional. Tier 0 elementary; 1 subsets; 2 short patterns/basic fish; 3 coloring; 4 chains/ALS/complex fish; 5 set/specialized/template methods; 6 forcing/generalized methods. Tiers describe a proposed explanation preference, not a difficulty rating.

Common profile bounds: ordinary/group chains <=24 inference links; generalized chains <=12 CSP-variable pairs; each ALS <=5 cells; grouped literals <=3 occurrences of one symbol in a house intersection; forcing <=128 derived nodes/branch before primitive expansion, <=2 nested branch levels, <=9 alternatives per split. Full proof caps apply afterward. A finite profile enumeration finishing is exhausted-within-bounds; interruption of that enumeration for work/time/bytes is incomplete. The exact supported parameter classes are those below, not arbitrary combinations of all listed technique names.

## 4. Generalized chains: distinct grammars

Use CSP-variable views for one cell's symbol choice and each house-symbol's location choice, backed by proved exhaustive cover clauses. Two candidates are linked only if an explicit conflict is proved. Generalized chains are not synonyms for AICs. Berthier distinguishes these generic families and application interfaces in [CSP-Rules](https://github.com/denis-berthier/CSP-Rules-V2.1) and develops chain/braid reasoning in [From Constraints to Resolution Rules, Part II](https://arxiv.org/abs/1304.3210). The implementation must pin the exact source revision used for names/fixtures; the grammar below is the finite engine contract.

Let target Z be assumed true. A sequence of CSP-variable pairs `(Li,Ri)` uses a complete variable alternative set Vi at each position. L1 conflicts with Z. In a continuous sequence, each later Li conflicts with the immediately previous Ri. At each pair all alternatives except Ri must have explicit conflict premises; Ri is then forced. A final variable has no compatible alternative and closes not-Z. Record excluded alternatives individually; different projected views of a candidate retain the same literal identity.

Extended supports 2×3 or 3×2 six-cell rectangles, <=3 core symbols, explicit nonidentity permutation preserving every affected house and clue. | `U02-hidden`, `U02-avoidable`, `U02-extended-2x3/3x2`, given-containing swap and nonpreserving box negative. |
| U03 | Unique Loops | Even loop of 4…12 cells, two core symbols, each affected house contains zero or two loop cells; no original given changed. <=4 extra guardian literals; core alternation enables a nontrivial preserved assignment swap. | `U03-length4/12`, odd loop, house touched once/three times and fixed-clue negatives. |
| U04 | BUG / BUG+1 | Entire residual board core is bivalue, each unplaced house-symbol has zero or two supports, no satisfied support counted again. BUG core must exhibit a nontrivial solution-preserving trade, checked structurally by alternate-cycle certificate. BUG+1 has exactly one extra candidate occurrence; infer it only after certifying the forbidden core. | `U04-core`, `U04-plus1`, odd support count and false residual core negative. A bare BUG core on independently unique input is an inconsistency diagnostic, not a deduction. |
| U05 | Generalized BUG / BUG+n | n=2…4 extra candidate occurrences over a checked U04 core; derive OR of every extra, then direct common conflict or <=24-link conditional forcing consequences. No arbitrary multivalue residual labeled BUG. | `U05-plus2/3/4`, missing extra occurrence, no trade certificate and invalid extra consequence negatives. |

D093 separates rectangle roof occurrences from the loop/BUG extra cap. U01 keeps every noncore occurrence in its four-cell/two-core geometry (at most 28); virtual subsets use at most four distinct extra symbols, which may occur on both roofs. U02 extended six-cell/three-core geometry has at most 36 noncore occurrences. The ordinary clause cap remains 64. New U consequence proofs count at most 24 distinct inference links per conditional case branch or single target-assumption DAG, not the sum across independent guardian cases; existing C22/C28 grammars remain unchanged; U03 separately retains its twelve-cell loop and four-guardian limits. Neither occurrence multiplicity nor source-clause length is a new case-split allowance. Unknown preservation of an affected declared rule is unsupported, never assumed from a necessary relation.

Definitions and uniqueness caveats are grounded in the author's [HoDoKu uniqueness discussion](https://hodoku.sourceforge.net/en/tech_ur.php). Andrew Stuart's [Extended Unique Rectangles](https://www.sudokuwiki.org/Extended_Unique_Rectangles), rechecked 2026-09-14, separately describes six-cell, three-symbol forms across three boxes; a familiar silhouette alone is insufficient without the specified transformation proof. Finite geometry, extra-candidate and link limits here are project bounds. Avoidable transformations preserve original clues and declared rules; they may change derived assignments, whose checked provenance must be included. The checker can reject an asserted familiar name even if some different conditional inference is sound. Unique-transform nodes always taint downstream ALS/chains/rollouts; discharge cannot erase this dependency.

## 7. Independent acceptance fixture contract

For every matrix row and each advertised named form/parameter class, create records under `web/tests/solver/fixtures/<row-id>.json` and provenance in `web/tests/solver/README.md`. The fixture set is authored/curated before enabling its detector. Do not use production output as its own answer. Record:

```ts
interface TechniqueFixture {
  id: string; rowId: string; grammar: string; alias: string;
  origin: { url: string | null; author: string; license: string; sourceRevision: string };
  givens: string; // 81 cells
  preState: { values: number[]; domains: number[] };
  expectedEffects: { kind: "place" | "remove"; cell: number; symbol: number }[];
  expectedPattern: object; // explicit named geometry/link/alternative contract
  expectation: "productive" | "reject" | "out-of-profile";
  reachability: "local-state" | "original-clue-path";
  oracleRecord: { method: string; inputHash: string; command: string;
    satisfiable: boolean; forceForbidExhausted: boolean };
}
```

Acceptance steps for a productive local state:

1. Independent set-based Algorithm X confirms at least one completion of the givens, assignments and candidate restrictions; this avoids vacuous unsatisfiable premises.
2. Detector emits the advertised named pattern with exact targets, not simply any solve step. Separate checker validates grammar, proof and effect set. Canonical symmetry tests exercise row/column/box orientations, digit permutations and min/max sizes.
3. Force each eliminated candidate in the pre-state and exhaust the independent oracle with no solution; forbid each placement and do the same. For U rows, prove unique from **original clues without candidate restrictions** first and separately validate the swap theorem on nonunique local-state examples. Oracle timeout is inconclusive and fails acceptance.
4. Mutation tests add an omitted support/fin/tuple/alternative, remove provenance, alter a group/RCC/strong link, exceed a structural bound, introduce an undischarged assumption or delete a proof chunk. Reject the claim with no state change.
5. At least one independently labeled original-givens puzzle for each row and advertised alias must actually exercise that detector on a replayable unconditional prefix (conditional prefix for U). A fixture solved earlier by another family does not certify named discovery; the harness may schedule the detector explicitly at the independently justified pre-state. No exact solution digits seed that state.
6. Freeze a positive boundary and one just-outside-profile rejection per adjustable structural dimension. Large equivalent subsets/fish may share a puzzle with separate expected pattern certificates; record alias/equivalent status honestly. Confirm before/after solution sets on exhaustible small residuals.

The independent oracle must not import production topology, mask/index helpers, detectors, proof checker, exact search or `domain/classic.ts`. Use a separate plain-loop grid checker and, for mock rules, full Cartesian enumeration. For templates and local trade/count certificates add a second small set/table enumerator. Record source licenses; do not copy a restricted puzzle collection without permission. If an original source is unsuitable for redistribution, generate a repository-owned analogous fixture and record that distinction.

Seed count fixtures remain repository-owned: existing `SOLUTION`, one hole at index 0, duplicate index 1=5, no-place rows `123456780`/`000000009` followed by zeros, rectangle holes 3/4/30/31, and empty. Independently verify their labels before using them. Coverage gating expands far beyond these seeds; these six boards do not certify advanced techniques.

## 8. Explicit limits without dropped families

Out-of-profile forms are unlimited chain/net depth, fish sizes >7 or complex fish >4, >4 fins, ALS size >5, aligned scopes >4, arbitrary non-Junior Exocets, unproved Exocet mirror/escape rules, non-ring generalized SK patterns, Tridagon geometries outside the four-box/12-cell schema, full nine-symbol overlay search, >4 Unique Loop guardian occurrences or BUG extra occurrences and custom variants. Keep them in manifest notes as unsupported generalizations, not pending hidden promises. Every requested family has a bounded planned form above; no release message may shorten that to “all techniques.” General unrestricted DFS, Bowman's Bingo and trial-and-error remain labeled fallback search, without a logical-family alias.
