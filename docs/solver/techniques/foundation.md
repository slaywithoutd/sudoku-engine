# Foundation techniques and coverage ledger

The manifest catalogues all 38 required M2 rows. This batch implements C01–C05
and mandatory all-different maintenance. C06–C33 and U01–U05 remain specified,
with no implementation or independent acceptance claim. Primary profile
membership is C01–C33; conditional membership additionally includes U01–U05.
The complete catalogue must not be described as a completed expanded solver.

`getTechniques(profile)` accepts only `classic-expanded@1` and
`classic-conditional@1`. Descriptors are immutable strategies with deterministic,
finite `discover` generators, explicit work events and explicit exhaustion.
An unavailable strategy is statically excluded with `specified-not-implemented`;
calling its discovery throws rather than emitting false exhaustion.
`profileReadiness` lists rows missing independent verification.
`assembleTechniqueJobs` checks the 256 rule-plus-descriptor job cap and rejects
an incomplete profile. Fixture tests may invoke implemented descriptors directly;
production controllers must use the readiness gate. This batch cannot produce
an expanded-profile stalled result. T19/T20 own controller integration.

The manifest preserves each matrix row's exact textual bounds, capabilities,
policy and tier. Descriptor numeric bounds project common scheduler dimensions;
the exact matrix includes additional incidence, fins, relation, table and branch
constraints. U rows use provisional explanation tier 6 under D070. C10 uses
four candidate vertices and three internal strong/weak/strong edges, plus target
conflicts. Changing these contracts requires versioned evidence.

## Proof and ownership boundaries

`ProofChecker.checkProposal` alone issues candidate-applicable `CheckedStep`
values. It authenticates original/imported nodes, checks primitive semantics,
matches every applied effect and exact edited-cell domain, and calls the closed
named grammar. The grammar imports neither discovery nor the descriptor registry.
Production checking first authenticates one captured source view through the
candidate owner's read-only `assertOwnedView` gate; structural lookalikes cannot
change the unresolved-cell count to mislabel a single or cache as Full House.
The checker/candidates dependency is a deliberate function-only module cycle:
neither module calls the other during initialization. Detector/registry/grammar
dependencies remain acyclic. Algebra-only certificate contexts are separate.
It restricts every newly computed node, the complete pattern, aliases, targets,
domain authority and bounds. A sound arbitrary table or forcing proof cannot
be relabeled as maintenance, a single or a subset.

`CertificateBuilder` only assembles untrusted IDs, imports and primitive records.
It cannot issue a Fact or CheckedStep or mutate candidates. Discovery strategies
compose it; checker strategies validate the independent primitive and family
contracts. The closed grammar lives in `techniques/grammar.ts`, below the
descriptor registry and independent of detector classes. No caller can register
arbitrary checking authority.

`verifyCertificate` is a separate, non-applying algebra verifier. Its opaque
`CheckedCertificate` has no candidate revision or step authority. Certificate
nodes have a different private identity store from accepted step nodes.
`CertificateSession` can retain these nodes for subsequent algebra verification;
it binds exact imports and never changes owned candidates. Production checking,
both reducers, replay and logical quality reject certificate-only authority.
Its individual checks enforce the supplied limits; it is not a solver-run or
transport accounting controller. The private admission selector is an unexported
module closure, not an erasable TypeScript-private method or caller option.

## Maintenance and named forms

Rule jobs use `rule-propagation@1`, outside the 38 named rows. Each all-different
job scans its finite ordered source/target pairs and proposes the direct live
peer exclusions from accepted values. Every exclusion is proved by a weak link,
resolution and explicit domain restriction. No candidate mask is pruned during
initialization, and maintenance never places a newly exposed singleton. Jobs
must be drained to a checked fixed point before a named selection window.

| Row | Discovery and checked certificate |
| --- | --- |
| C01 | One unresolved singleton; `Naked Single`. `Full House` and `Last Digit` additionally name a covering house with exactly one unresolved cell. One placement and every currently live peer exclusion are explicit. |
| C02 | Rebuild every cell's support from a proved cover and accepted domains, require one remaining support, then place with explicit peers. A smaller all-different cage supplies no existence cover. |
| C03 | A nonempty proper cover/group intersection contains all 2–3 supports. Prove each explicit outside target by the support clause and bounded weak-link resolutions. `pointing`/`claiming` check box/line orientation; `Locked Candidates`/`direct forms` are equivalent presentations. A direct single remains a later C01/C02 step. |
| C04 | Canonical naked/hidden pairs, triples and quads. Naked sets require exact Hall cardinality. Hidden sets require all selected symbols' complete supports and use the complementary Hall set for effects. Complementary 5/6/7 presentations explicitly record the direct 4/3/2 form; both directions have independent examples. Empty effects and deficient three-cell/two-symbol unions are not useful subset deductions. |
| C05 | An unresolved pair/triple in a classic box-line intersection. Each applicable house has separately proved productive Hall roots. Only their checked union is advertised; duplicate effects retain both supporting roots. A pattern lying in only one house is rejected. |

The checker permits bounded C01/C02 proof-only singleton caches. They contain
one newly proved positive literal (at most two nodes), retain the same revision,
and reject already retained equivalent facts. They are never atomic candidate
transactions. Existing scoped/table primitive tests use certificate-only
verification instead of temporary unrestricted `roots` maintenance certificates.
Future families must add their own closed cache grammar before retaining newly
computed table or graph facts through production replay/transport.

## Independent acceptance

`tests/solver/fixtures/C01.json` through `C05.json` contain repository-owned
original-clue fixtures. A separate author used plain Python sets and house
geometry to label C01–C05, including all intersection orientations/support
sizes, naked/hidden sizes and house orientations, complementary directions and
locked pair/triple orientations. The authoring construction witness is never
passed into production state or proofs. The durable reproduction command is:

```text
cd web
npm test -- tests/unit/solver/foundation.test.ts tests/unit/solver/coverage.test.ts
```

`fixtureView` reconstructs each expected pre-state solely through checked direct
original-given exclusions. `discoverFixture` matches the exact independently
labeled pattern and effects; its productive accessor requires exactly one
matching proposal. Negative callers inspect proposals/status without reading
that accessor. `fixtureCertificate` separately compiles the explicit fixture
geometry into a DAG without calling production discovery or builder code.
`checkFixtureMutation` clones that independent certificate and drains the real
checker after the named mutation; it never reruns discovery.

The acceptance oracle is separate Algorithm X, with no production topology,
masks, checker, discovery or exact search imports. Every productive pre-state
must have a witness, every removed candidate is forced and every placement is
forbidden with exhaustive zero-witness results. Inconclusive oracle work fails
acceptance. All 81 C01 cells and all 243 classic house-symbol C02 covers are
checked, in addition to multivalue C02 originals. Each advertised alias has a
replayed original-clue prefix, independently compiled certificate and mutations
for alias, structural bound, missing node/import, altered effect/domain and
open scope. No exact solution digits seed a candidate restriction.

The fixture helpers are test-only and are not a runtime scheduler, renderer or
proof transport. Performance/heap/cancellation and full expanded-profile release
gates remain later tasks. Work events are bounded cursor checkpoints, not a
claim that all profile enumeration fits a default time budget.
