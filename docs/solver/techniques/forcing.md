# Forcing chains, nets and Kraken Fish

C22 branches over a candidate's true/false alternatives, all live symbols in
one cell, or all live supports of one house and symbol. Each case proves the
same literal or a contradiction; the complete case cover discharges every
temporary assumption. A positive conclusion produces a placement and explicit
peer removals. Nishio assumes one candidate true and uses only that digit's
house covers and weak conflicts until contradiction.

C23 composes C01–C05 propagation and scalar resolution inside confined
hypothetical sessions. Static graph clauses come from original parent domains.
Dynamic graph construction uses the exact checked branch domains and retains
their proof identities; its named certificate must consume a newly available
binary link. Nested forcing exhausts an actual cell's alternatives at a second
lexical level. It never invokes the human scheduler, exact search or MRV DFS.

C24 assumes the target true, derives every fin false, then applies the same
checked cover-count certificate used by C07/C08 fish. Its independent grammar
rechecks the entire fish incidence geometry and every fin path. Sharing fish
geometry validation does not grant direct-visibility authority to Kraken.

## Bounds and counting

C22 allows 2–9 complete alternatives and at most 24 links per branch, including
both paths when complementary literals establish a contradiction. C24 allows
C07/C08 fish of size 2–4, at most four fins and at most 24 links per fin path.
Scalar links alternate signs, so a target-positive to fin-negative path has
odd length: the independently admitted 23-link Kraken recipe is its attainable
maximum under that cap. C22 separately admits a real 24-link positive result.
All supplied positive, negative and domain effect roots must descend from the
named complete certificate. A valid unrelated proof cannot decorate it.

C23 allows at most two actual lexical assumptions and 128 derived semantic
inference nodes per branch before primitive expansion. The checker counts
each `resolution@1`, `hall@1`, `cover-clause@1`, `contradiction@1` and `cases@1`
node at its exact lexical scope. Each propagated candidate exclusion and each
link resolution counts individually; a multi-effect basic step is never one
budget unit. Assumptions, immutable domain restriction storage, weak clauses
and support filtering are primitive scaffolding. A complete house cover still
has a separately counted cover-clause inference. Sibling scopes have separate
counters; the outer cases inference belongs to its parent scope.

The ordinary checker additionally enforces expanded node, serialized byte,
retained-run, work and time limits. Discovery reserves graph, branch and proof
storage through the caller's `IndexWorkspace`. Hitting a bound or cancellation
returns an interruption, never a contradiction. `time-limit` supplements the
existing work, proof and workspace interruption reasons. Local checker time
and operation deadlines are tracked separately. Only completed enumeration
returns `exhausted`; missing capabilities remain watched exclusions.

Measured certificate sizes are distinct from author operation counts:

| Certificate | Semantic nodes per branch | Expanded nodes | Serialized bytes |
| --- | --- | --- | --- |
| Independent static | 18 | 45 | 14,530 |
| Independent nested | 22 outer; 12/7 inner | 96 | 23,693 |
| Independent dynamic maximum | 128 | 312 | 62,040 |
| Independent dynamic outside profile | 129 | 314 | 62,138 |

The129 certificate is independently mathematically valid and its effect has
an exhausted counterfactual oracle check. Ordinary named admission rejects it
with `net-node-out-of-profile`. The128 certificate is admitted and replayed
from original clues. These are complete dependency-bearing proofs, not tests
of a synthetic counter. Actual discovery is independently tested for all three
net modes; exact128 is a recipe-admission boundary, not a claim that the
production cursor selects that particular schedule or that shorter proofs fail.

## Confined branch authority

`forkView(parent, label, workspace)` requires an authentic parent publication
and reserves storage before copying buffers, indexes and prefix bookkeeping.
The engine allocates unique branch identities. Labels, state-shaped objects,
numeric node IDs and caller-supplied scope arrays confer no authority.

`new HypotheticalSession(parent, label, workspace)` owns that fork. Its `view`
getter returns the current immutable publication. `assume(literal, limits)`
checks the assumption and initial restriction; `check(proposal, limits)`
returns a separately branded `BranchCertificate`; `publish(certificate)`
accepts only a certificate from that exact source publication. Facts, domains
and indexes publish atomically. A checked false/empty-domain result cannot be
published as a usable view.

`dispose()` releases the session reservation and revokes every borrowed view,
including cold index rebuilds. Held views and certificates cannot start fresh
checking, indexing or publication after disposal. `disposeFork(view)` is the
equivalent cleanup for a directly borrowed fork. Every additional cold branch
index reserves storage before allocation. Primary views keep their established
closed-root admission contract.

Ordinary `checkProposal`, `verifyCertificate`, `commitChecked` and
`retainCheckedFacts` reject every hypothetical view, including assumption-free
forks. Branch admission authenticates exact immutable proof-node objects and
their source/ancestor ownership. Read-only ancestry queries expose booleans or
immutable scope values, never mutable owners or registration callbacks.

The final parent proof is freshly replayed through ordinary admission. Net DAG
import maps node objects to fresh global IDs, so colliding sibling numeric IDs
cannot alias. Premises and lexical scopes are rewritten. The supported local
rules have no node-bearing parameters; nonempty local parameters are rejected.
Final named metadata is reconstructed entirely from remapped node IDs; local
pattern metadata is not copied as authority. The final proof has its own
reservation and can outlive disposed branch sessions.

## Implementation and independent evidence

`ForcingProof` compiles explicit untrusted recipes. `ForcingGraph` owns a frozen
invocation graph and bounded signed-path search. `ForcingLineage` checks exact
edge/source/case lineage independently of discovery. The net runtime composes
existing basic strategy objects with a session and identity-based DAG importer.
The registry exposes `c22@1`, `c23@1` and `c24@1` through their normal descriptors;
`discoverNetCandidate` exposes the same bounded targeted net strategy for tests.

Fixtures preserve original clues, exact domains and independently authored
operations. `tests/solver/forcing-acceptance.ts` separately reconstructs basic
geometry and compiles certificates through test algebra. Tests check ordinary
admission, satisfiable prestates, exhausted forced-opposite counterfactuals and
complete original-clue replay. Actual discovery is tested separately from
recipe compilation. Read the fixture provenance for honest reuse and measured
boundary limitations; catalogue evidence must not imply minimal difficulty.
