# Uniqueness-dependent techniques U01-U05

These techniques run only in `classic-conditional@1` after an independently accepted original-problem uniqueness result. Their conclusions and every descendant remain conditional. They cannot improve the primary logical result or qualify a solution as Perfect.

## Named forms and finite bounds

| Row | Admitted forms | Geometry and consequence bounds |
| --- | --- | --- |
| U01 | Unique Rectangle types 1-6 | Four nongiven cells, two rows, two columns, two boxes, two-symbol core. Complete roof OR has at most 28 literals. Type 3 virtual subset sizes 2-4 count distinct extra symbols separately from roof occurrences. Type 5 supports two or three roofs. |
| U02 | Hidden, Avoidable, Extended Rectangle | Hidden requires a bivalue opposite corner; the target may have extras. Avoidable types 1 and 2 require authenticated derived placements. Extended supports both six-cell orientations with three symbols and at most 36 noncore occurrences. |
| U03 | Unique Loops | Even simple loop of 4-12 cells; each affected house meets two opposite-parity cells. At most four guardian occurrences. |
| U04 | BUG, BUG+1 | Complete residual board, bivalue core, zero or two unsatisfied house-symbol supports, exactly one guardian. "BUG" is the named +1 inference; a bare zero-guardian core is a diagnostic, not a productive deduction. |
| U05 | Generalized BUG, BUG+n | Complete residual core with two through four guardian occurrences, including four extras distributed across two trivalue cells and a four-candidate cell. |

Every conditional case branch, or single target-assumption denial DAG, contains at most 24 distinct causal implication links and one assumption level. Shared prefixes count once only when they are the same checked nodes with the same causal predecessor. Different guardian branches are counted separately. The general clause cap remains 64; an eight-literal rectangle roof OR is not truncated to four. Loop length and consequence length are separate bounds.

Type 6 checks the selected symbol's restrictions in both rows and both columns. Both diagonal-roof removals form one atomic transaction. Each removal has its own complete denial DAG; the union of those DAGs uses the selected parallel strong-house pair. The unused orthogonal pair remains mandatory geometry, without decorative proof nodes.

## Responsibilities and proof authority

`UniqueTransformChecker` in [unique.ts](../../../web/src/solver/proof/unique.ts) checks a complete trade certificate: all current domains, all original clue handles, every declared rule handle, exact nongiven trade cells, complete guardians and a nontrivial solution-preserving transformation. It does not consult a solved grid. Two-symbol complementary trades use all-different multiset preservation; the six-cell three-symbol permutation is checked by bounded complete local enumeration. An affected non-all-different rule is rejected because its declared semantics have no exact preservation certificate. Disjoint unchanged rules are allowed. A necessary/derived relation capability is not evidence that its whole declaring rule is preserved.

The untrusted compiler [unique-compiler.ts](../../../web/src/solver/techniques/unique-compiler.ts) composes the existing forcing proof builder. The independent [unique-grammar.ts](../../../web/src/solver/techniques/unique-grammar.ts) checks named geometry, complete causal paths, selected effects and imported source identity. `UniqueRectangles`, `UniqueLoops` and `Bug` own bounded geometry enumeration; `UniqueConsequenceSearch` composes the implication index for finite consequence search. Registry descriptors provide uniform eligibility, limits and discovery events. Missing authority produces `{kind:"disabled",reason:"missing-unique-authority"}`; consumers must handle this explicitly rather than treating it as exhaustion.

`acceptedUniqueParent(count, context, quarantined)` in [evidence.ts](../../../web/src/solver/evidence.ts) accepts only the actual merged CountEvidence, matching primary run, authentic unconditional accepted path and current non-invalidated/non-quarantined controller context. It returns an opaque `AcceptedUniqueParent` exposing only `evidenceId`. `uniqueParentDetails(parent)` is a read-only authenticated projection of the original snapshot, run, assembly and immutable accepted prefix; it exposes no witness. `revokeUniqueParent(parent)` permanently invalidates all handles of that accepted count.

`ConditionalOperation.begin(parent, run, limits, workspace)` creates an independent owned branch named `conditional:<requestId>`. `rebuildPrefix()` initializes from original clues, deterministically rebinds only proposal/proof state envelopes and independently checks and commits every primary prefix bundle. `uniqueAuthorityOwns(authority, view)` binds lifetime bookkeeping during this prefix-only phase. `uniqueAuthorityMatches(authority, view)` additionally requires the entire accepted prefix to have completed and authorizes the unique primitive. A forged brand, matching evidence string, cloned count or independently initialized same-label owner grants nothing.

The private constructor receives either authentic accepted steps or bounded decoded proposals. It reserves reference storage and charges projection work before making its single immutable proposal-reference array; `begin` does not allocate a preliminary mapped copy. A failed work/storage/deadline gate disposes the initialization lease before any capability escapes.

Every CheckedStep created inside the operation is privately bound to its active authority. Candidate commit and retained-fact publication recheck that binding, including otherwise unconditional transactions. Existing checker reachability rejects unused proof nodes; permanent taint prevents a reachable conditional ancestor from becoming an unconditional root. `checkAndCommit(proposal)` and [replayConditional](../../../web/src/solver/proof/replay.ts) retain these checks and cumulative work/header/resource limits. Ordinary `replay` continues to reconstruct the primary branch only. Conditional replay requires the exact operation branch and prefix-ready state; it never imports saved CheckedStep objects or calls discovery.

`acceptedOriginIdentity(view)` is a read-only opaque identity query for an authentic accepted owner, excluding hypothetical views. A private constructor-owned weak map binds this identity to its operation; `conditionalViewAuthority(view)` retrieves it for lifetime bookkeeping even after disposal. Omitting `CheckContext.uniqueAuthority` therefore cannot bypass revocation for ordinary C01/C33 transactions. Explicit foreign authority rejects, and commit/retain requires the step's private binding to match the target origin. These queries create no authority and do not implicitly enable unique primitives: the caller must still provide an explicit ready capability. Independent owners with identical branch labels retain ordinary semantics. Saved conditional bundles replay only into the same bound run; a new request rebuilds the unconditional primary prefix and replaces the prior conditional result.

`operation.usage` reports cumulative initialization/bootstrap-hash/check/commit work, cumulative header bytes and elapsed milliseconds. `remainingLimits()` exposes remaining time/work/header allowance and available workspace while retaining total run-node/proof semantics. The scheduler passes remaining limits to discovery and reports its consumed work through `operation.charge(units)`; it must never restart with original limits after prefix replay. `isConditionalOperation` is a read-only replay owner query, not a factory.

Conditional cancellation/rerun calls `operation.dispose()` and preserves primary count/parent eligibility. Parent-wide revocation is for changed original input, primary replacement or quarantine. The controller must invoke it before accepting more work when that lifecycle changes.

## Trusted worker bootstrap and codec handoff

`operation.digestPrefix()` uses [captureConditionalPrefix](../../../web/src/solver/conditional-prefix.ts). Its public result is data only: `{descriptor:{bundles,nodes,bytes,digest},proposals,lease}`. `copy=false` retains immutable main prefix references; `copy=true` captures worker data and transfers a workspace lease to the receiver until disposal. The helper never issues proof or candidate authority.

Each proof header (with empty node array) and each node is captured through the existing bounded data-copy boundary with a 16 KiB cap. Keys are sorted canonically within each bounded record. SHA-256 hashes the header followed by ordered node hashes into each bundle hash; the prefix hash includes ordered bundle hashes and the versioned exact bundle/node/byte counts. Header slot zero and separate bundle framing distinguish empty bundles and all boundaries. Full proposal/prefix JSON strings are never constructed. Byte/hash/copy buffers are reserved before allocation, work is charged, and cancellation/lifetime/deadline are checked after asynchronous digest calls. Partial failures release both temporary buffers and accumulated captured records. SHA-256 supplies identity integrity, never authority.

`operation.grantBootstrap(port, nonce, generation)` posts a complete control frame capped at 32 KiB and returns a `ConditionalBootstrap` envelope with full RunKey, snapshot/problem, prefix descriptor, one-use nonce and active generation. It retains the actual accepted parent on the controller. `ConditionalOperation.installTrustedBootstrap(port, expected, assembly, limits, workspace, driver?)` is an explicit TRUSTED worker-runtime installation boundary; proof/data dispatch must never call it. It returns `{ready, providePrefix, dispose}`. The dedicated installed MessagePort must receive the exact single grant; foreign-port, stale/changed and duplicate grants cannot activate it. `providePrefix` accepts one already bounded/reassembled body, independently captures and hashes it, matches the complete descriptor, and rechecks every prefix bundle. `ready` exposes the operation only after both grant and full prefix replay. The optional `ConditionalReplayDriver` supplies `yieldTask(): Promise<void>`; it must yield a real task. The default uses `setTimeout(0)`. Prefix replay pauses after at most 256 reported work units, locks replay before the first await, and rechecks lifetime/deadline on resume; duplicate frames cannot start another replay. A MessagePort does not authenticate against hostile JavaScript in the same realm.

T20/T21/T23 must implement Start `conditional:{prefix:{bundles,nodes,bytes,digest},authorizationPort}|null`, transfer the dedicated peer port once, send prefix chunks no larger than 64 KiB with at most two credits and preallocation accounting, then `prefix-end` / `prefix-ack`. They emit `conditional-ready` only after this adapter's `ready`. No full proof prefix or CountEvidence belongs in the grant/control frame. They must tear down ports/owners on cancellation, replacement, bad frames and worker termination, observe both promise failures, and keep the original immutable accepted prefix on main. Before accepting worker output, main independently checks `operation.acceptsResult(run,prefixDescriptor)` and its active lifecycle; it must not wait for worker revocation delivery. Worker transport/reassembly must account its own buffers before passing them to the codec. The separate Node worker test exercises realm isolation and the actual adapter; browser/Vite worker integration remains those runtime tasks.

Main-side `grantBootstrap` claims its dedicated endpoint synchronously before the first hash await. Concurrent reuse rejects without closing the first caller's endpoint. Once claimed, an endpoint remains consumed even if hashing, accounting or posting fails; failure closes it, and retry requires a new MessageChannel. Successful grants remain attached to operation disposal for revoke and close.

## Acceptance records

[unique-techniques.test.ts](../../../web/tests/unit/solver/unique-techniques.test.ts) checks original-clue uniqueness and each claimed opposite with an independent exact-cover oracle, independently reconstructed domains/trades/wire certificates, the production compiler and production discovery for every admitted form. It includes both rectangle orientations, virtual triple/quad, Hidden extra target, both avoidable forms, loop lengths 4/12 and out-of-profile 14, and BUG+1/+2/+3/+4. Prefix recipes labeled C22 despite actual singleton domains are normalized to genuine C01 with assertions of identical full atomic effects; historical author labels remain construction metadata only.

[unique-boundaries.test.ts](../../../web/tests/unit/solver/unique-boundaries.test.ts) checks independently authored, primitive-valid 24/25-distinct-link target DAGs and a 25-link case DAG whose individual paths are shorter than 24. Only the named out-of-profile forms reject. [unique-integration.test.ts](../../../web/tests/unit/solver/unique-integration.test.ts) tests actual retained U03 clauses through C28 and actual unique placements through C33, independently assembled and production-compiled consumers, production discovery, commit, taint, primary/Perfect refusal and fresh conditional replay. No test imports a source fact issuer.

[unique-provenance.test.ts](../../../web/tests/unit/solver/unique-provenance.test.ts), [unique-negative.test.ts](../../../web/tests/unit/solver/unique-negative.test.ts) and [unique-resources.test.ts](../../../web/tests/unit/solver/unique-resources.test.ts) cover private authority, readiness, same-label owners, port isolation, cancellation, revocation, strict sources, mixed-rule preservation, resource cleanup and record limits. Catalogue entries remain implemented pending the root's independent review; acceptance evidence does not itself promote status.
