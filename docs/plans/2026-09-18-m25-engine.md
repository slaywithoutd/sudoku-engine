# M2.5 Engine implementation plan

**Status:** written 2026-09-18 under D100; awaiting the user's go before the first code commit.
**Spec:** [M2.5 engine design](../specs/2026-09-17-engine-design.md) (approved, D100). Section references below (§) point to it.
**Branch:** `feat/m25-engine` from `master` at `82a9af1`. One commit per task; each task ends with its own tests green, an independent review of the diff, and fixes committed before the next task starts. Merge into `master` only after T17.

All `src/` and `tests/` paths are relative to `web/`; `docs/` paths are repository-root relative.

## Global constraints (from the spec and existing decisions)

- No literal `81`, `9` or `27` in new files (§3.1); T11 adds the grep test.
- No UI change; variant problems exist only as `EngineProblem` constraint instances in tests and corpus (§3.2).
- Every logical deduction is checked by the existing named-grammar + primitive path; no test bypass mints accepted steps (D052, D071).
- Exact-phase `prune` is trusted evidence code, never a proof premise (§3.13).
- Production code cannot import tests; the variant oracle cannot import `src/solver` (D052).
- Policy ids and every parameter enter `optionsKey` (D094).
- Heavy checks run sequentially on this machine (vitest ≈ 25 min alone; never with tsc/eslint concurrently). `coverage.test.ts › preserves exact UTF8 matrix bounds` is a known pre-existing failure on `master`; T17 restores the doc path it reads or moves the test's source.

## Review protocol per task

1. Implement with tests; run only the affected test files plus `typecheck`.
2. Commit `feat(solver): <task>`.
3. Independent review of the diff by a separate reviewer agent that has not seen the implementation reasoning; findings are fixed and committed as `fix(solver): <task> review`.
4. The task's line in `docs/history/m25-implementation-progress.md` records commit, tests run and review outcome.
